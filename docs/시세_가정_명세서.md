# 시세 가정 명세서 — 시세 추정·대조군(Comp) 구성의 암묵적 가정 전수 목록

> **목적** (감사체계 2026-07-23, harness/AUDIT_RUNBOOK.md): 시세 트랙의 오류는 파싱 미탐이 아니라
> **가정 오류**(이름 매칭 → 엉뚱한 단지 혼입 → 시세 튐)에서 나왔다. 감사가 뭘 공격할지 정하려면
> 코드에 박힌 가정을 전부 표출화해야 한다. 이 문서가 그 단일 목록이다.
> 각 가정 = 문장 · 근거(파일:라인) · 깨지는 시나리오 · 반증 쿼리 초안 · 위험도.
>
> 작성: 독립 코드 정독 에이전트(2026-07-23), 대상 = naver_match/naver_client/naver_store/matcher/
> molit_bridge/molit_client/compare/pipeline(시세부)/score(신뢰도부)/pricechart + 관련 테스트.
> **유지 규칙**: 시세·매칭 코드를 수정하면 이 문서의 해당 가정도 갱신한다(문서 드리프트 큐 대상).

**감사 한계 (선결 고지)**: `scored_listings.market_comps`는 `[(deal_ym, price), ...]`만 저장하고 그 comp이 "어느 단지 이름에서 왔는지"는 저장하지 않는다. 즉 "대조군에 다른 단지가 섞였는가"를 auction.db만으로 직접 카운트할 수 없고, 대부분의 반증 쿼리는 **간접 신호**(비율 이상, 스코프 라벨 분포, 밴드 폭)에 의존한다. 이 자체가 ⑥ 폴백/결측 카테고리의 한 항목이기도 하다.

## ① 단지 동일성 (대조군 정체성)

### A1. "좌표로 특정한 cortar(격자) 내 후보 단지 중 이름최고유사도 = 진짜 그 단지다"
1. **가정**: `cortar_for(lat,lng)`로 얻은 법정동 격자 안의 네이버 단지 목록에서 `best_complex()`가 고른 최고점 후보가 경매물건의 실제 단지다.
2. **근거**: `deploy/crawl_naver.py:295-306`(`cortar_for`→`complexes_in`→`best_complex`), `src/naver_match.py:62-80`. 주석(`naver_client.py:294`)에 "좌표별 cortar 캐시(~110m 반올림)"라 명시.
3. **깨지는 시나리오**: courtauction 소재지 좌표(지오코딩)가 아파트 입구가 아니라 동 중심·인접 필지로 잡혀 cortar가 옆 법정동으로 튀면, 진짜 단지는 후보군에 없고 이름이 비슷한 이웃 단지가 최고점이 됨. 후보군 자체가 틀리면 `accept()`의 이중임계도 걸러내지 못한다.
4. **반증 쿼리 초안**:
```sql
SELECT np.court, np.case_no, np.item_no, sl.apt_name, np.complex_name, np.match_conf
FROM naver_prices np JOIN scored_listings sl
  ON sl.court=np.court AND sl.case_no=np.case_no AND sl.item_no=np.item_no
WHERE np.match_conf IN ('고신뢰','중신뢰');
-- ↑ 결과를 파이썬에서 naver_match.name_score(apt_name, complex_name) 재계산해
--   accept() 기준(0.85+area<=5 / 0.70+area<=1.0)을 실제로 만족하는지 재검증(로직 회귀 검사).
```
5. **위험도**: 상 — 상류 단지 오확정은 estimate_from_complex_trades까지 "확정 comps"로 그대로 흘러가 SAME_COMPLEX_EST_MIN(0.35)만으로 걸러야 한다.

### A2. "이름이 부분문자열로 포함되면(2자 이상) 같은 단지다" — 국토부 이름매칭 폴백 경로
1. **가정**: `matcher._by_name()`에서 `name in norm(t.apt_name) or norm(t.apt_name) in name`이면 같은 단지로 간주(면적·동 조건과 AND).
2. **근거**: `src/matcher.py:229-238`.
3. **깨지는 시나리오**: "주공", "현대", "우성", "삼성", "한신" 같은 흔한 이름이 "주공1단지"/"주공2단지" 등 서로 다른 단지에 공통 포함됨. `_multi_complex()` 가드는 **숫자 식별자(N단지/N차)가 이름에 명시된 경우에만** 작동(`_COMPLEX_ID_RE`), 텍스트 식별자(가/나/A동, 1BL, 동편/서편)나 식별자 없음 케이스는 여전히 오염 가능. `tests/test_matcher.py` 픽스처는 완전 일치 케이스만 테스트해 이 리스크 미검증.
4. **반증 쿼리 초안**:
```python
# 정적 검증: 같은 동 내 서로 다른 apt_name 쌍 중 부분문자열 포함이면서
# _complex_ids가 양쪽 다 빈(=숫자 가드 무방비) 쌍의 개수
from src.matcher import _norm, _complex_ids
pairs = 0
for a, b in itertools.combinations(distinct_apt_names_same_dong, 2):
    if len(a) >= 2 and (_norm(a) in _norm(b) or _norm(b) in _norm(a)):
        if not _complex_ids(a) and not _complex_ids(b):
            pairs += 1  # 가드 무방비 오매칭 후보
```
5. **위험도**: 상 — "이름 매칭으로 엉뚱한 단지가 섞이는" 사고 유형의 1차 용의 코드.

### A3. "N단지/N차 숫자 식별자가 다르면 다른 단지다" — 두 곳에 중복 구현
1. **가정**: `matcher._complex_ids`/`naver_match._complex_ids`가 정규식 `r"(\d+)\s*(?:단지|차)"`로 뽑은 식별자 집합의 교집합 유무로 동일 단지 여부 판정.
2. **근거**: `src/matcher.py:180-196`(`_multi_complex`), `src/naver_match.py:52-80`(3c 가드) — 같은 로직이 두 파일에 독립 구현.
3. **깨지는 시나리오**: 숫자 아닌 식별자(가/나/A/B, 동편/서편)는 전혀 안 잡힘. "힐스테이트 2차 3단지"류 예외 처리가 이미 필요했던 휴리스틱이라 신규 표기 패턴에 계속 뚫릴 수 있다.
4. **반증**: tests/test_naver_match.py에 텍스트 식별자 케이스 전무 — 커버리지 부재 자체가 반증. 표본 수작업 확인 필요.
5. **위험도**: 중 — 이미 두 차례 실사고(2026-07-12 #2, 2026-07-20 3c)로 발견·패치된 반복 패턴.

### A4. "네이버 확정(complexNo/areaNo)이면 이름 매칭이 필요 없다" — 상류 오류 그대로 전파
1. **가정**: `estimate_from_complex_trades`는 상류 확정을 전제로 이름 재검증을 전혀 안 한다.
2. **근거**: `src/matcher.py:384-391` 주석 "이름 문자열 매칭을 우회한다".
3. **깨지는 시나리오**: 상가/지하유닛이 소형 주거유닛에 오매칭된 실사고 실측(matcher.py:49-51, 용인역북 est/감정 0.106). 하한가드(SAME_COMPLEX_EST_MIN=0.35)는 극단 붕괴만 잡고 중간 왜곡(0.5~1.8배)은 통과.
4. **반증 쿼리 초안**:
```sql
SELECT court, case_no, item_no, apt_name, est_market_price, appraisal_price,
       ROUND(1.0*est_market_price/appraisal_price, 3) AS ratio, market_scope
FROM scored_listings
WHERE market_scope='same_complex_same_area'
  AND (1.0*est_market_price/appraisal_price < 0.5 OR 1.0*est_market_price/appraisal_price > 1.8)
ORDER BY ratio;
```
5. **위험도**: 상.

### A5. molit_bridge: "그룹키(kind, apt_name, dong, 면적반올림) + 지문(월,가격,층) 3건·2배 우위면 동일 단지다"
1. **가정**: `BridgeIndex.topup()`의 정확일치 지문 매칭이 이름 유사도 없이도 안전하다.
2. **근거**: `src/molit_bridge.py:64-125`.
3. **깨지는 시나리오**: 신축 대단지의 표준화 분양가 구조에서 동일 시군구·법정동·면적의 **다른 단지**가 (월,층,가격) 조합을 3건 이상 우연히 공유할 확률이 0이 아니다.
4. **반증**: molit_cache(data/molit_trades.db)에서 같은 (lawd,dong,면적) · 낮은 이름유사도 그룹 쌍의 (deal_ym,price,floor) 교집합 ≥3 쌍 카운트.
5. **위험도**: 중 — 안전장치 다겹(MIN_MATCHES=3·COVERAGE 0.6·WINNER_MARGIN 2.0)이나 통계적 우연 일치에 최종 의존.

### A6. "법정동 문자열이 같으면 같은 지역이다" — lawd_cd 없는 레거시 경로에서 무방비
1. **가정**: `match_trades_scoped`/`_by_name`의 지역 필터가 `t.lawd_cd` 빈 값이면 통과.
2. **근거**: `src/matcher.py:216-225` "레거시 빈 값은 통과".
3. **깨지는 시나리오**: `pipeline.load_sample_trades()`가 만드는 Trade는 lawd_cd 미태깅 — 비live 경로에서 지역필터가 조용히 꺼짐. 프로덕션 노출은 run.py dryrun 가드로 차단되나, 다른 호출부가 가드 없이 재사용하면 즉시 재발.
4. **반증**: `load_sample_trades()` 전건 lawd_cd 채움율 실측(전건 미태깅 예상).
5. **위험도**: 하(서빙 미노출) / 중(구조 함정).

## ② 면적/평형 동치

### B1. "같은 평형 = ±3%(SAME_AREA_BAND), 인접 평형 = ±10%(AREA_BAND)"
- 근거: `src/matcher.py:21-22, 241, 244`. 상대비율이라 대형(150㎡)은 ±15㎡까지 허용(다른 타입 혼입), 초소형(20㎡)은 ±2㎡로 표본 고갈→폴백행.
- 반증: 오피스텔 25㎡ 미만의 폴백/no_comps 비율을 대형과 대조.
- 위험도: 중.

### B2. "네이버 평형타입 중 전용면적 최근접 1개가 정답 타입이다"(best_area)
- 근거: `src/naver_match.py:83-99`. 진짜 평형이 목록에 없으면 최근접 표준 평형이 고신뢰 채택될 수 있고, 5㎡ 절대 허용치는 평형대별 상대 관용도가 다름.
- 반증: 같은 (complex_no, area_no)의 실거래 exclusive_area 산포(mx-mn>4㎡) 그룹 카운트.
- 위험도: 중.

### B3. "같은 areaNo면 개별 면적 편차 무시 가능" — median 계산 시 면적 정규화 생략
- 근거: `src/matcher.py:390-391`. 발코니 확장형/비확장형이 같은 타입코드로 묶이면, 정규화 생략 의도와 반대로 왜곡 재도입.
- 반증: B2 쿼리 재사용.
- 위험도: 중.

## ③ 시점/신선도 (실거래 유효기간)

### C1. "표본 내 가장 최근 거래월 = 오늘" — filter_recent의 기준점 ⚠
- 근거: `src/matcher.py:279-286` — cutoff가 오늘이 아니라 **comps 내 최신 거래월** 기준. 거래절벽 단지는 옛 고점 시세가 "최근 12개월"로 계속 통과. 급락장 초입에서 구조적 위험.
- 반증: market_comps 최신월 vs sale_date 격차 ≥6개월 물건 플래그(파이썬, JSON 파싱 필요).
- 위험도: **상**.

### C2. "표본 부족 시 창 24→60개월 확장 + 신뢰계수 하향이면 가격 왜곡도 상쇄된다"(WINDOW_LADDER)
- 근거: `src/matcher.py:378-381` — 주석 스스로 "가격은 방어되지만 신뢰 부풀림은 방어 안 됨" 인정. mult는 점수만 낮추고 **표시 시세 숫자는 60개월 median 그대로**.
- 반증: 동일 (complex,area)의 12개월 vs 60개월 median 괴리 >15% 그룹 플래그.
- 위험도: **상**.

### C3. "네이버 확정 경로(창 계층화)와 국토부 폴백(고정 12개월)의 신선도 정책이 달라도 비교 가능하다"
- 근거: estimate_market은 RECENCY_WINDOW 12 고정, estimate_from_complex_trades만 LADDER. 같은 scope 라벨을 공유해 사용자에겐 동일해 보임.
- 반증: `SELECT market_scope, market_source, COUNT(*) ... GROUP BY market_source`.
- 위험도: 중.

### C4. "KB/호가/전세 폴백은 fetched_at 나이와 무관하게 '현재' 시세다" ⚠
- 근거: `src/score.py:306-345` 어디에도 신선도 체크 없음. 재크롤 스킵된 물건의 수개월 전 KB/호가가 계속 폴백 서빙.
- 반증:
```sql
SELECT np.court, np.case_no, np.status, np.fetched_at
FROM naver_prices np JOIN scored_listings sl
  ON sl.court=np.court AND sl.case_no=np.case_no AND sl.item_no=np.item_no
WHERE sl.market_source IN ('kb','ask','lease') AND np.fetched_at < date('now','-180 day');
```
- 위험도: **상**.

### C5. molit_bridge: "닫힌 달 캐시가 곧 진실 — 사후 해제신고 미반영 안전"
- 근거: `src/molit_bridge.py:127-131` 주석 자체 명시. 뒤늦은 해제 거래가 확정 comps로 영구 잔류 가능.

## ⑤ 밴드/대표값 산출

### E1. "표본 4건 이상이면 상·하 1건씩 트림으로 이상치 방어 충분"(trim_outliers)
- 근거: `src/matcher.py:264, 300-304`. 4~5건 표본에서 한쪽 몰림 이상치에 취약, 정상 표본도 과잉 축소.
- 반증: 4~6건 그룹의 트림 전/후 median 변화율 분포.
- 위험도: 중.

### E2. "band_low(최저 평단가)는 항상 안전마진" — 3건 표본에서 트림 미발동 ⚠
- 근거: `src/matcher.py:362-363`, band_min_basis=3 < TRIM_MIN_SAMPLES=4. 3건 중 최저가가 가족간 저가양도면 그게 그대로 '보수적 하한'.
- 반증:
```sql
SELECT court, case_no, market_sample_basis, market_band_low, market_band_high
FROM scored_listings
WHERE market_sample_basis=3 AND market_band_high>0
  AND 1.0*market_band_high/market_band_low > 1.3;
```
- 위험도: **상**.

### E3. "FALLBACK_BAND_SPREAD_MAX=1.6배가 폴백 오염을 보편적으로 가른다"
- 근거: `src/matcher.py:34-38` — 실측 1건(1.748배)에서 역산한 단일 임계. 분산 큰 지역의 유효 시세가 과잉 무효화될 수 있음(안전방향).
- 반증: `market_scope='band_too_wide'` 건수·분포 표본조사.
- 위험도: 하.

### E4. "감정가는 신선하고 정확하다" — 감정평가 시점 정보가 모델에 없음 ⚠
- 근거: `src/matcher.py:40-52`, models.AuctionListing에 감정평가일 필드 부재. 감정~기일 시차의 시장 변동을 코드가 모름 → 상승장 저평가 물건/하락장 정상 시세가 'appraisal_mismatch'로 오분류돼 **표본 손실이 은폐**.
- 반증: appraisal_mismatch 무효화 건수 추이(시차 정보 부재 자체가 반증).
- 위험도: **상**.

### E5. "median이 시세를 대표한다" — 3건 표본의 통계 착시
- 근거: `src/config.py:126-132`, band_min_basis=3. 3건 median = 중간 1건 가격. "median"이라는 용어가 실제 통계력보다 과장.
- 반증: `market_sample_basis IN (3,4)` 비중.
- 위험도: 중.

### E6. pricechart: "표시 band_now는 항상 12개월 창 값이다"
- 근거: `src/pricechart.py:111-150` — WINDOW_LADDER 확장 여부(mult)가 ScoredListing에 미영속이라 60개월 밴드가 12개월 밴드처럼 그려짐(신뢰 하향 정보 UI 유실).
- 위험도: 중.
