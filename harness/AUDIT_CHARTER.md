# AUDIT_CHARTER — 감사 헌장 (각 감사의 지향점)

> 절차는 `AUDIT_RUNBOOK.md`, 발견 기록은 `AUDIT_CASEBOOK.md`. **이 문서는 "왜/무엇을 향해"를 정한다.**
> 감사 코드를 새로 만들거나 고칠 때, 그 감사가 아래 지향점에서 벗어나지 않는지 먼저 확인한다.

## 0. 전체 지향점 — 감사가 존재하는 이유

이 서비스는 사용자에게 **"이 물건은 사도 된다"**고 말한다. 그 말이 틀리면 사용자가 돈을 잃는다.
감사의 목적은 코드를 예쁘게 만드는 게 아니라, **그 말의 근거가 사실인지 계속 의심하는 것**이다.

**3원칙**

1. **위험한 오류는 한쪽 방향에만 있다.** "위험 있음"이 틀리면 기회를 놓칠 뿐이지만,
   "문제없음"이 틀리면 사용자가 손해를 본다. 따라서 감사는 **항상 "문제없음" 판정을 표적**으로 한다.
2. **모름은 없음이 아니다.** 서류가 침묵하면 "모름"이지 "없음"이 아니다.
   미상을 0원·clean·해당없음으로 바꾸는 모든 코드 경로가 감사 대상이다.
3. **케이스가 아니라 클래스를 고친다.** 발견된 물건 하나를 수리하는 것은 감사의 실패다.
   "어떤 가정이 깨졌나"를 찾아 그 클래스 전체를 막고, 회귀 테스트로 잠근다.
   (예외처리를 무한히 쌓는 대신 지식을 축적한다 — `AUDIT_CASEBOOK.md`)

**공통 성공 기준**: 회차를 반복할수록 **새로 발견되는 클래스가 줄어드는 것**.
불일치 건수가 아니라 *새로운 유형*의 감소가 신뢰의 지표다.

## 1. 블라인드 물건 감사 (Layer 1 · 권리 트랙)

- **코드**: `scripts/audit_pack.py` → 격리 폴더 판독 → `scripts/audit_compare.py`
- **질문**: 지금 DB에 있는 물건의 **권리 판정이 사실과 맞나?**
- **지향점**: 우리 파서·가정에 오염되지 않은 **독립된 뇌**가 서류 원문만 보고 내린 판정과,
  우리가 사용자에게 보여주는 판정이 **일치하는가**. 불일치는 오류 확정이 아니라 **심문 개시**다.
- **독립성의 근거 2가지** (이게 깨지면 감사 자체가 무의미):
  ① **정보 차단** — 판독관에게 우리 판정·코드·CLAUDE.md를 주지 않는다(레포 밖 격리 폴더에서 실행).
  ② **방법 차이** — 프로덕션은 키워드 정규식, 판독관은 자연어 날짜 추론. 읽는 방식 자체가 다르다.
- **정확도 규칙**: 케이스당 독립 판독관 2~3명, **2/3 합의만 채택**. 제각각이면 '판독 불안정'으로 분류하고
  오류 선언에 쓰지 않는다.
- **표본 규칙**: 적대적(= "문제없음"으로 서빙 중인 추천등급 위주) + 법원 층화 + 감사 이력 제외.
  표본의 절반은 `AUDIT_CASEBOOK`의 **형제 가설** 표적에 배정한다.
- **성공 기준**: 라운드를 반복해도 **새 클래스가 안 나오는 상태**. 불일치율 자체는 0이 목표가 아니다
  (판독관도 틀리므로).
- **한계**: 판독 깊이는 꾸러미에 담긴 서류의 양에 종속된다. 현황조사서·등기부가 없으면 '판단불가'가 는다.

## 2. 리스팅 완전성·충실성 감사 (Layer 1+2 · 리스팅 트랙)

- **코드**: `scripts/audit_listing_fields.py`
- **질문**: **공짜로 주는 데이터를 다 가져오고, 변형 없이 저장하는가?**
- **지향점**: "우리가 안 보는 필드"를 사람의 기억이 아니라 **기계적 전수 대조**로 찾아낸다.
  법원 응답의 모든 키 × 코드 참조 여부를 대조해, **채움율은 높은데 코드가 한 번도 안 읽는 키**를 드러낸다.
  (`mulBigo` 1,583건·`spJogCd` 15,303건이 이 방식으로 발견됐다.)
- **핵심 통찰**: 자유 텍스트를 정규식으로 추측하는 대신, **원천이 이미 구조화해 준 값**이 있는지 먼저 본다.
  구조화 값이 있으면 그것이 1차 근거이고, 텍스트 판정은 교차검증 수단이다.
- **성공 기준**: 미참조 키 목록이 전부 "안 써도 되는 이유"가 문서화된 상태.
  (미사용 = 무조건 나쁨이 아니다. 예: wgs84 좌표는 정수부만 와서 무의미 — **정당한 미사용**)
- **한계**: 정적 문자열 검색이라 동적 접근(`obj[key_var]`)은 놓칠 수 있다. 판정은 항상 실물 확인 후.

## 3. 시세 가정 반증 스윕 (Layer 2 · 시세 트랙)

- **코드**: `scripts/audit_market_assumptions.py` (근거 목록: `docs/시세_가정_명세서.md`)
- **질문**: **우리가 시세를 계산할 때 믿고 있는 가정들이 실제로 참인가?**
- **지향점**: 시세의 오류는 파싱 미탐이 아니라 **암묵적 가정**에서 나온다
  (이름이 비슷하면 같은 단지다 / 표본 안 최신 거래가 오늘이다 / 미상이면 0이다).
  따라서 감사의 1단계는 **가정을 문서로 꺼내는 것**이고, 2단계는 가정마다
  **"이게 깨진 실물이 DB에 몇 건인가"**를 세는 것이다. 추상적 우려를 **건수**로 바꾼다.
- **성공 기준**: 모든 '위험 상' 가정에 반증 쿼리가 붙어 있고, 위반 건수가 회차마다 추적되는 상태.
- **정직 규칙**: **깨지지 않은 가정도 반드시 보고한다.** (C4·D1은 0건이었다)
  감사기가 "다 문제"라고 말하기 시작하면 아무도 감사를 안 믿는다.
- **한계**: `market_comps`에 "어느 단지에서 온 comp인지"가 저장돼 있지 않아, 대조군 오염을
  직접 카운트할 수 없고 간접 신호(비율·분산)에 의존한다. → 저장 스키마 보강이 선행 과제.

## 4. 크롤 파서 충실성 감사 (Layer 2 · 전 트랙) ← 크롤링 **코드**를 감사

- **코드**: `scripts/audit_parser_fidelity.py` (재료: `listing_detail_raw` 원본 보존)
- **질문**: **크롤러가 받은 원문을, 파서가 누락·변형 없이 컬럼에 옮겼는가?**
- **지향점**: 위 1~3번이 "결과가 맞나"를 물었다면, 이건 **"수집→저장 과정 자체가 정직한가"**를 묻는다.
  원본(raw)과 파싱 결과(컬럼)를 **같은 물건에 대해 1:1로 대조**해, 원문에는 있는데 컬럼엔 없는 값
  (누락), 원문과 다른 값(변형), 원문에 없는데 컬럼에 생긴 값(중복·오염)을 찾는다.
- **왜 이제야 가능한가**: 종전엔 normalize 후 원본을 버려서 사후 대조가 **물리적으로 불가능**했다
  (QA F1). 2026-07-23 원본 보존 배선으로 재료가 생겼다. **감사는 원본 보존 없이 성립하지 않는다.**
- **성공 기준**: 보존된 원본 전건에 대해 (누락·변형·중복) 0건. 위반은 파서 버그로 직결되므로
  발견 즉시 fixture 동결 → 회귀 테스트.
- **한계**: 원본 보존 이후 크롤분만 대조 가능(소급 불가). 커버리지는 재크롤 진행에 따라 자연 증가.

## 5. 무료 격차 감사 (Layer 2 · 권리·리스팅 트랙) — 예정

- **질문**: 법원이 무료로 여는 엔드포인트 중 **우리가 아예 안 치는 것**이 무엇인가?
- **지향점**: 4번이 "받은 것을 잘 저장했나"라면, 이건 "**받을 수 있는데 안 받은 것**"을 찾는다.
  유료 사이트가 보여주는 항목(관련사건·문건송달·낙찰가율 등)을 기준선으로 삼아 격차 목록을 만든다.
  (분석은 공개 화면·문서 열람만 — 유료 사이트 데이터 크롤은 금지: `LOOP.md` 범위 잠금)

## 6. 표출 정합 감사 (Layer 1 · 전 트랙) — 후순위

- **질문**: DB가 맞아도 **화면이 거짓말하지 않는가?** (목록·상세·API·CSV 4곳 일치)
- **지향점**: 삼환 사례처럼 상세는 "⛔권리미확인"인데 목록은 초록 "차익 유력"인 모순을 자동 검출.
  더해서 "이 문구를 초보자가 보면 뭐라고 이해할까"(모름을 없음처럼 보이게 하는 표현)까지 판독.
- **주의**: 이것은 **정합** 감사다. "소비자에게 정말 편한가"를 묻는 **UIUX 사용성 감사는 별도 트랙**이며,
  데이터 정합과 섞지 않는다(운영자 정의, 2026-07-23).

## 감사 운영 규칙 (공통)

- **파일럿 기간**(라운드 1~3): 발견을 기록만 하고 코드는 고치지 않는다. 결과가 재현되는지 먼저 본다.
- **확정 절차**: 불일치 → 원문 재확인(필요 시 보완 크롤) → **원문 증거로만** 확정 → CASEBOOK 기재
  → fixture 동결 → 회귀 테스트 → 클래스 수정 → versions.md.
- **크롤 예산**: 감사는 저장 데이터 우선. 재수집이 필요하면 안전 클라이언트(예산·스로틀·킬스위치 공유)를
  통해서만, 표적 보완 크롤로(전량교체 금지).
- **감사기도 틀린다**: LLM 판독·정적 검색·정규식 모두 오탐을 낸다. 실물 확인 없이 오류를 선언하지 않는다.
