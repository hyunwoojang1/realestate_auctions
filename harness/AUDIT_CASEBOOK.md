# AUDIT_CASEBOOK — 크롤·판정 오류 원장 (오답노트)

> **목적**: 감사(블라인드 판독 대조)에서 **확정된** 오류를 축적한다. 단순 수리 기록이 아니라,
> 다음 감사가 "이 오류의 형제가 다른 데도 있지 않을까?"를 묻는 **가설의 원천**이다.
>
> **운영 규칙**
> 1. 기재 자격: 대조관 심문을 통과해 원문 증거로 **확정**된 오류만. (블라인드 판독 불일치만으로는 미기재)
> 2. 매 감사 시작 전, 이 원장을 읽고 **형제 오류 가설**을 만든다 → 그 회차 표본의 절반을 가설 검증에 배정.
> 3. 각 항목은 반드시 5요소: 증상 / 원문 증거 / 깨진 가정 / 클래스 수정 / 회귀 테스트.
> 4. 수정은 케이스가 아니라 **클래스**를 고친다 — 이 원칙이 예외처리 지옥과의 차이다.

## 형식

```
### C-### | YYYY-MM-DD | 트랙(리스팅/권리/시세) | 심각도
- 증상:       (무엇이 틀리게 서빙됐나)
- 원문 증거:   (fixture 경로 또는 원문 인용)
- 깨진 가정:   ("코드는 ___라고 가정했지만 실제로는 ___")
- 클래스 수정: (커밋 해시 + 무엇을 일반화했나)
- 회귀 테스트: (tests/ 파일::테스트명)
- 형제 가설:   (같은 가정이 숨어 있을 만한 다른 위치 — 다음 감사 표적)
```
