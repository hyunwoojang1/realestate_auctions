## 감사 1회차 절차

0. **형제 가설**: `harness/AUDIT_CASEBOOK.md`를 읽고 과거 확정 오류의 형제 가설을 만든다.
   표본의 절반은 가설 표적, 절반은 적대적 랜덤.
1. **출제**: `.venv/Scripts/python.exe scripts/audit_pack.py --n 10`
   — "클린 서빙 중" 물건 위주(적대적) + 법원별 층화 + 감사 이력 제외(harness/audit_state.json).
   꾸러미는 blind 폴더 inbox/, 정답지는 harness/audit/<round>/manifest.json (블라인드 폴더 반입 금지).
2. **판독**: 케이스당 독립 판독관 3명 — 세션에서 병렬 서브에이전트, 또는 blind 폴더에서
   `claude -p` 헤드리스. 출력: `verdicts/<case>__r1..r3.md`. 판독관에게 레포·우리 판정 언급 금지.
3. **대조**: `.venv/Scripts/python.exe scripts/audit_compare.py` → `harness/audit/<round>/REPORT.md`
   - 일치 / CRITICAL(합의=있음·위험 vs 우리=없음) / HIGH(합의=판단불가 vs 우리=없음) / 불안정
4. **심문**: CRITICAL·HIGH 케이스는 원문을 직접 재확인(필요 시 표적 재수집 = 보완 크롤, 물건 행만
   업서트·전량교체 금지). LLM 판독도 틀릴 수 있다 — **원문 증거로만 확정**.
5. **확정 처리**: CASEBOOK 기재(5요소) + fixture 동결 + 회귀 테스트 + **클래스 수정** + versions.md.
6. **지표**: 회차별 불일치율 기록 — 0 수렴 여부가 "크롤을 믿어도 되는가"의 정량 답.
