## P1 — 인수 부담이 0원으로 계산되어 추천되는 것 (P-01 · P-13)

- **현상**: 명세서에 "매수인에게 대항할 수 있는 임차권등기… 잔액을 매수인이 인수함"이 **명시**된 물건이
  `assumed_amount=0` 으로 계산돼 차익 유력·양호·관심으로 서빙. **추천 573건 중 108건(19%)**.
  상세 화면은 인수를 표시하는데 API·CSV는 금액이 비어 있어(53/53) **화면과 데이터가 다른 결론**.
- **깨진 가정**: "인수 금액이 미상이면 0원(=부담 없음)이다" — 모름을 없음으로.
- **수정 방향**:
  1. 판정에 **"인수 확정 · 금액 미상"** 상태를 1급 시민으로 도입(현재는 금액 없으면 그냥 0).
  2. 그 상태면 **등급 상한 강등**(추천계열 진입 금지 — 주의/위험 계열로).
  3. API·CSV에 `assumed_amount: null` 대신 **"미상" 플래그**를 명시하고, CSV '유효차익'은 **공란**
     (0으로 빼서 계산하지 않는다 — 판단 불가는 판단 불가로).
- **테스트**: 인수 문구 + 금액 미상 → ① 등급이 추천계열이 아님 ② API에 미상 플래그 ③ CSV 유효차익 공란.
- **영향 실측(수정 전)**: 추천 108건 · 인수문구 전체 1,329건 · 금액0 계산 646건.

## P2 — 대항력 검증 자료가 추천 물건에 구조적으로 0% (P-08 · P-10)

- **현상**: 추천 573건의 현황조사서 커버리지 **0%**. 원인 둘 —
  ① `_tenant_targets` 가 `rights_verified=0` 을 요구(추천은 전부 =1) → 교집합 구조적 0,
  ② 일일 스케줄러가 `AUCTION_CRAWL_TENANTS`·`--tenants-backfill` 을 **아예 안 켬**.
- **왜 P1 다음인가**: 이걸 고쳐야 "요지가 침묵해서 안전 판정한 205건"을 검증할 수단이 생긴다.
  다음 감사의 판독 깊이도 여기에 종속된다.
- **수정 방향**:
  1. `_tenant_targets` 에 **"추천등급(서빙 기준 포함) + 요지 빈칸"** 클래스를 최우선 대상으로 추가.
  2. 일일 스케줄러에 소량(예: 50~100건/일) 배선 — **밴 예산 안에서**. 크롤 페이싱 정책 준수.
- **테스트**: 대상 산출 함수가 추천+요지빈칸 물건을 우선 반환하는지(픽스처 DB).
- **영향 실측(수정 전)**: 추천 573건 중 tenants 보유 0건 · 요지 빈칸 205건 · 백필 대상 1,273건(추천 0).

## P3 — 서빙 재계산이 모든 검증의 사각지대 (P-12)

- **현상**: 서빙 추천 **634건** vs DB 추천 573건 → **61건이 어떤 게이트·감사도 통과한 적 없음**(7건 인수문구).

  가장 단순한 안 = 서빙 재계산 결과를 저장(또는 채점 단계에서 같은 폴백을 적용해 DB와 서빙을 일치시킴).
  ※ 감사 도구 쪽은 이미 `audit_pack.py --serving` 으로 선반영(2026-07-23).
- **테스트**: DB 등급과 서빙 등급이 일치하거나, 불일치 시 게이트가 그 사실을 검출.

## U-01 입찰보증금 — 함수 완료 · **배선 인계** (2026-07-23 15:5x)

⚠️ **동시 작업 알림**: 다른 세션이 같은 시각 재매각 기능(`resale_history`·상세 경고 배너·목록 칩)을
`templates/detail.html`·`src/web.py`·`src/courtauction_detail.py`에 **미커밋 상태로 구현 중**이다.
충돌을 피해 **순수 함수와 테스트만** 커밋하고 화면 배선은 넘긴다.

**제공되는 것** (`src/courtauction_rights.py`, 테스트 `tests/test_bid_deposit.py` 12종):
```python
parse_deposit_rate(*texts) -> int | None      # 명세서에서 보증금 비율(%) — 없으면 None(= '미상')
bid_deposit(min_bid_price, *texts) -> (금액, 비율, 법원명시여부)
```
- 실측 표기 7변형 대응("특별매각조건 매수신청보증금 최저매각가격의 20%" 등, DB 609건 기준)
- 범위 밖(10~30% 외) 값은 오탐으로 버림, 여러 개면 **큰 값**(현금 과소평가 방지)
- **None은 10%가 아니라 '법원이 명시 안 함'** — 호출부가 '통상 10% 가정'으로 쓰되 추정임을 표시할 것

**해야 할 배선 1곳** — `templates/detail.html` 입찰보증금 KPI(현재 `s.min_bid_price * 0.1` 하드코딩):
```jinja
{# web.py 상세 뷰에서: deposit_amt, deposit_rate, deposit_stated = bid_deposit(
       s.min_bid_price, rights.remark, rights.lien_note, rights.surviving_rights) #}
입찰보증금 <span class="s">{% if deposit_stated %}(법원 명시 {{ deposit_rate }}%){% else %}(통상 10% 가정 · 공고 확인){% endif %}</span>
{{ won(deposit_amt) }}
```
- 명시값이 있으면 **라벨이 아니라 금액 자체**가 바뀌어야 한다(현재는 라벨만 "재매각 20~30%"로 바뀌고
  숫자는 10%인 상태 — UX 감사 U-01의 핵심 미해결분).
- 미명시(stated=False)면 금액을 단정하지 말고 '가정'임을 같은 줄에 밝힐 것.

**영향 실측**: 법원이 10%가 아닌 비율을 명시한 물건 **309건**(20% 302 · 30% 7),
그중 **추천등급 24건**. 예: 인천 2024타경584394(관심) 화면 0.07억 → 실제 0.14억.
