# 초보자를 위한 아파트 경매 1차 필터 (realestate_auctions)

> **아파트 경매 후보의 시세·권리·유찰 리스크를 보수적으로 걸러주는 검토 보조 도구**의 PoC.
> 한 줄로: *"실거래와 경매가의 괴리를 보여주되, 어디까지 믿어도 되는지 함께 말해주는 1차 필터."*
> (사라고 콕 집어주는 엔진이 아닙니다 — 어떤 수치도 입찰 판단을 대체하지 않습니다.)

법원경매 물건의 **최저입찰가**와 **국토부 실거래 가격 밴드(검증 하한가~기준가)**를 매칭하고,
취득세 등 객관 비용을 차감한 **보수 기준 차익**(하한가 − 취득원가)을 계산해 후보를 걸러줍니다.
핵심 가치는 높은 수익률 표시가 아니라 **"이 데이터를 어디까지 믿어도 되는지"를 명확히 알려주는 것**:
비교군 출처(같은 단지/같은 평형 여부)·표본 수·신뢰 게이트를 모든 수치에 병기합니다.

---

## 왜 만들었나 — 시장의 빈칸

국내 사설 경매정보 사이트(지지옥션·스피드옥션·탱크옥션·옥션원·태인 등)와 신흥 AI 서비스(요이땅·땅집고·미스고 등) 20여 곳을 분석한 결과, 공통된 구조적 공백이 있었습니다.

> **거의 모든 사이트가 "안전한가(권리분석)"에는 과잉투자했지만, "돈이 되는가(차익)"는 비워뒀다.**

- 레거시 사이트는 시세를 "참고시세/인근 매각사례" 수준으로만 보여주고, **"최저입찰가 vs 실거래 시세 = 예상차익"을 자동 계산해 랭킹·정렬·알림으로 밀어주지 않습니다.**
- "반값경매" 같은 테마 큐레이션도 대부분 **감정가 대비 할인율**일 뿐, **실거래 시세 대비 차익**이 아닙니다. (감정가는 시세가 아닙니다 — 이 착시가 핵심입니다.)

이 프로젝트는 그 빈칸 — **실거래 시세 대비 차익을 1급 정렬키로 삼는 큐레이션** — 을 채웁니다.

### 이 PoC가 검증하는 3가지
1. **시세 대비 싼(차익 큰) 물건을 자동으로 상위에 올린다.**
2. **차익이 커 보여도 권리가 더러우면(인수금액 과다·유치권) "위험"으로 강등한다** (하드게이트).
3. **시세 추정이 안 되는 물건(실거래 매칭 0건)은 거짓 차익을 만들지 않고 "시세추정불가"로 분리한다.**

## 어떻게 작동하나

```
[경매 물건]                 [국토부 실거래]
 최저입찰가·감정가·권리      아파트/연립다세대/오피스텔
      │                          │
      └──────────┬───────────────┘
                 ▼
         ┌──────────────┐
         │   매칭/시세추정  │  단지명+전용면적 ±10% → 법정동 폴백
         │  (matcher)    │  평단가 중앙값 × 전용면적 = 추정시세
         └──────┬───────┘
                ▼
         ┌──────────────┐
         │  차익 스코어 엔진 │  가격갭50 + 권리30 + 환금20, ×신뢰계수
         │   (score)     │  + 하드게이트(인수>30%·유치권 → 위험)
         └──────┬───────┘
                ▼
      SQLite 저장 → 콘솔 랭킹표 / CSV / HTML 리포트
```

## 차익 스코어 (0~100)

```
score = ( 가격갭 × 0.50 + 권리 × 0.30 + 환금성 × 0.20 ) × 신뢰계수(0.6~1.0)

실질취득원가 = 최저입찰가 + 취득세 + 명도비 + 수리비 + 인수금액
가격갭       = (추정시세 − 실질취득원가) / 추정시세
```

| 하위점수 | 가중치 | 무엇을 보나 | 데이터 소스 |
|---|---|---|---|
| **가격갭** | 50% | 부대비용 차감 후 시세 대비 할인율 | 법원경매 + 국토부 실거래 + 세율 룰 |
| **권리 깨끗함** | 30% | 인수금액 비율·특수권리·대항력 임차인·명도난이도 | 등기·매각물건명세서·현황조사서 |
| **환금성** | 20% | 물건종류·지역유동성·거래회전 | 실거래량 + 자체 낙찰결과 DB |
| **신뢰계수** | ×0.6~1.0 | 시세 추정 표본 밀도 | 실거래 매칭 건수 (3↑=1.0 / 2=0.85 / 1=0.7 / 0=시세추정불가) |

### 하드게이트 (제품의 핵심 안전장치)
**인수금액/최저가 > 30%** 또는 **치명적 유치권**이 있으면 → 권리 점수를 0으로 만들고, **최종 스코어를 상한(25)으로 끌어내려 "위험" 등급으로 강등**합니다.

> 권리 점수만 0으로 만드는 것으로는 부족합니다. 가격갭 가중치가 50%라, 갭이 큰 유치권 물건이 여전히 "양호"로 상위 노출될 수 있기 때문입니다. 그래서 최종 점수 자체를 끌어내립니다. (이 허점은 개발 중 자동 발견·수정되었습니다.)

### 등급
`차익 유력`(80+) · `양호`(60~79) · `관심`(40~59) · `주의`(<40) · `위험`(하드게이트) · `차익없음`(보수 기준 차익≤0) · `시세추정불가`(표본 부족) · `미지원유형`(아파트·오피스텔 외) · `권리미확인`(권리분석 전)

> "확실한/확정"류 단정 표현은 쓰지 않습니다 — 법원경매에서 보장되는 차익은 없습니다.
> 추천 인정 조건: 같은 단지·같은 평형 비교군 + 근거 표본 5건 이상 + 보수 기준 차익 양수 + 하드게이트 미발동.

> **틀릴 수 있는 계산을 확정적으로 보여주지 않는 것**이 이 도구의 핵심 동작입니다.

## 웹 서버 (사이트)

브라우저에서 차익 매물을 열람·필터하는 Flask 사이트.

```bash
# 로컬 실행
python -m flask --app src.web run        # http://127.0.0.1:5000

# Docker
docker build -t auction-arb .
docker run -p 8000:8000 auction-arb      # http://localhost:8000
```

| 경로 | 설명 |
|---|---|
| `/` | 1차 필터 목록 (보수 기준 차익순, 갭미터·경고뱃지) + 필터 폼(보수차익/종류/지역/정렬) |
| `/property/<사건번호>` | 물건 상세 — 갭미터 특대·차익 근거·권리 안전성(하드게이트 사유)·환금성 |
| `/methodology` | **투명성** — 차익 스코어 공식·가중치 + 백테스트 캘리브레이션(스코어↔실현수익) 공개 |
| `/digest` | 이번 주 차익 TOP N |
| `/api/listings?min_score=80&type=아파트&region=서울&sort=profit` | JSON API (필터 쿼리) |
| `/api/listings/<사건번호>` | 단건 JSON |
| `/health` | 헬스체크 |

> 데이터는 PoC 샘플. 국토부 키(`.env`의 `MOLIT_API_KEY`)를 넣으면 라이브 시세로 전환됩니다(F10).

## 정기 새로고침 스케줄러 (Windows)

전국 courtauction 실매물 + 국토부 시세 매칭을 매일 자동으로 돌려 `auction.db`를 갱신합니다.
웹 서버는 이 DB를 그대로 읽어 서빙하므로, 새로고침과 서빙이 분리됩니다.

```powershell
# 오프라인 dry-run (네트워크 호출 0 — 캐시/샘플 fixture로 파이프라인 검증)
powershell -File scripts\refresh-daily.ps1 -FromCache -Cash 100000000

# 작업스케줄러 등록 (매일 05:30) — 등록 직후 상태는 반드시 Disabled(비활성)
powershell -File scripts\install-scheduler.ps1 -Time 05:30

# 등록 계획만 미리보기(실등록 없음)
powershell -File scripts\install-scheduler.ps1 -Time 05:30 -WhatIf

# 등록 해제
powershell -File scripts\uninstall-scheduler.ps1
```

> ⚠️ **활성화는 이용약관 확인 후 수동으로.** `install-scheduler.ps1`은 작업을
> **Disabled(비활성)** 상태로만 등록합니다. courtauction/국토부 이용약관을 확인한 뒤
> 아래 한 줄로 활성화하세요:
>
> ```powershell
> Enable-ScheduledTask -TaskName "AuctionArbitrage-DailyRefresh"
> ```
>
> 이는 자동화가 약관 확인 없이 실서버를 호출하는 것을 막기 위한 안전장치입니다.
> 활성화 전까지는 스케줄이 등록만 되어 있고 실행되지 않습니다.

`refresh-daily.ps1` 옵션:

| 옵션 | 설명 |
|---|---|
| `-Live` | 국토부 라이브 시세 사용(`MOLIT_API_KEY` 필요). 스케줄러 기본 |
| `-FromCache` | **오프라인 dry-run**: 실크롤/라이브 시세 미호출, 캐시(`data\courtauction_cache.json`) 또는 샘플 fixture로 파이프라인 실행 |
| `-Cash <원>` | 가용현금 상한(최저가 ≤ 현금 매물만) |
| `-Ym <YYYYMM>` | 국토부 조회 연월(미지정 시 전월) |
| `-DbPath <경로>` | 대상 SQLite(미지정 시 `auction.db`) |

로그는 `evidence\refresh-YYYYMMDD-HHmmss.log`에 남습니다.

## 데이터 소스 (라이브, F10)

| 데이터 | 소스 | 비용 | 비고 |
|---|---|---|---|
| 아파트/연립다세대/오피스텔 실거래가 | 국토교통부 실거래가 API (data.go.kr) | **무료** | 운영자 키 발급 필요 |
| 경매 물건 | 대법원 법원경매정보 | — | PoC는 샘플 fixture, v1에서 크롤러 |

### 국토부 API 키 발급 (라이브 실행용)
1. [공공데이터포털](https://www.data.go.kr) 회원가입
2. "국토교통부_아파트 매매 실거래가 자료" 오픈API → **활용신청** (무료·대부분 자동승인)
3. 발급 인증키를 `.env`에 입력 (`.env.example` 복사):
   ```
   MOLIT_API_KEY=발급받은_키
   ```
4. `python run.py --live --ym 202605`

> ⚠️ 유료 경매사이트의 가공 데이터를 크롤링하지 않습니다. 데이터는 **원천(대법원·국토부 등)에서만** 수집합니다.
