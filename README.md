# 부동산 경매 차익 큐레이션 (auction-arbitrage)

> **법원경매에 나온 아파트·오피스텔을 "실거래 시세 대비 얼마나 싼가(차익)"로 자동 랭킹하는 사이트.**
> 한 줄로: *"실거래와 최저입찰가의 괴리를 보여주되, 그 시세를 어디까지 믿어도 되는지 함께 말해주는 1차 필터."*

**프로덕션:** https://auction-arbitrage-nine.vercel.app

법원경매 물건의 **최저입찰가**를 **국토부 실거래 가격밴드**(검증 하한가~기준가)와 매칭하고, 취득세 등 객관
비용을 차감한 **보수 기준 차익**을 계산해 후보를 걸러줍니다. 핵심 가치는 높은 수익률 표시가 아니라
**"이 데이터를 어디까지 믿어도 되는지"** 를 모든 수치에 병기하는 것입니다(비교군 출처·표본 수·신뢰 게이트).

이 프로젝트에서 **가장 중요한 엔진은 크롤링 계층**입니다 — 여러 원천(대법원 법원경매·국토부 실거래·
네이버 KB시세/호가·건축물대장)을 각기 다른 방식으로, **차단당하지 않고 정중하게** 수집해야 나머지
매칭·스코어가 성립하기 때문입니다. 이 README는 그 크롤링 로직을 자세히 설명합니다.

# 크롤링 엔진 상세

> 이 프로젝트의 심장. 4개 원천을 각기 다른 프로토콜·차단정책으로 수집하며, **원천(대법원·국토부)에서만**
> 수집하고 유료 경매사이트의 가공 데이터는 크롤링하지 않습니다.

## 공통 설계 — 밴(차단) 회피 철학

여러 곳을 긁을수록 차단 위험이 커지므로, 모든 크롤러가 공유하는 원칙을 먼저 둡니다.

| 원칙 | 구현 |
|---|---|
| **순차 전용(병렬 금지)** | courtauction·naver는 concurrency=1. 한 IP에서 동시요청은 즉시 봇 신호. |
| **랜덤 지터 지연** | 요청 간 고정간격이 아니라 매번 난수 지연(courtauction 3~8초, naver 2~4초). 고정간격=봇. |
| **일일 총량 상한** | courtauction `daily_cap=500` — 인스턴스 누적 요청이 넘으면 서킷브레이커로 중단. |
| **지수 백오프** | 429/5xx는 `2→4→8…`초 백오프(+지터). `Retry-After` 헤더가 오면 그 값(최소 60초) 존중. |
| **차단 시 우회 금지** | 403·리다이렉트 감지 시 **즉시 중단**. 헤더 바꿔 뚫는 우회를 하지 않음(합법·정중 전제). |
| **조용한 차단(silent block) 감지** | 200인데 비-JSON/스키마 붕괴/HTML 챌린지면 "위장 차단"으로 보고 중단 — '데이터 없음'과 구분. |
| **kill-switch 파일** | `COURTAUCTION_STOP`/`NAVER_STOP` 파일이 존재하면 다음 요청 전 즉시 종료(수동 급정지). |
| **개인정보 미저장** | 파서 단계에서 임차인·소유자 성명 등은 추출하지 않고 **불리언·금액·유형만** 남김. |

> 국토부(molit)는 공식 공공 API이고 안티봇이 없어 **병렬(ThreadPool) 허용** — courtauction/naver와
> 정책이 다릅니다. "어디를 긁느냐에 따라 다른 정책"이 이 엔진의 핵심입니다.

## ① 대법원 법원경매 (courtauction) — 가장 중요한 크롤러

`src/courtauction_client.py` · `src/courtauction_fields.py` · `src/courtauction_detail.py`

경매 물건의 **원천**입니다. 사이트에 뜨는 모든 매물이 여기서 나옵니다.

### 엔드포인트 (실측 리버스 엔지니어링)
```
GET  /pgj/index.on                              → 세션 쿠키 발급(워밍)
POST /pgj/pgjsearch/searchControllerMain.on     → 물건 검색(목록)
POST /pgj/pgj15B/selectAuctnCsSrchRslt.on       → 물건 상세(권리·기일·청구금액·사진)
```
`www.courtauction.go.kr`는 화면만 있고 공개 API 문서가 없어, Playwright로 실제 브라우저의 XHR을
캡처해 페이로드·헤더 구조를 역설계했습니다.

### 수집 흐름
1. **세션 워밍** — `GET /pgj/index.on`으로 세션쿠키(`wcCookieV2`)를 받습니다. 이 쿠키에는
   **클라이언트 IP가 박혀** 있어서, 가정용 동적 IP가 도중에 바뀌면 쿠키가 무효화됩니다(→ 차단 감지로 드러남).
2. **카나리 요청** — "서울 부동산 1페이지"처럼 반드시 결과가 나오는 쿼리로 정상 응답형태를 먼저 확인.
   0건이 오면 조용한 차단으로 보고 시작조차 안 함.
3. **서버사이드 필터** — 요청 총량을 줄이려 **작동이 확인된 필터만** 사용합니다(실측: 지역·감정가·최저가율·
   면적·유찰횟수만 서버에서 동작). ⚠️ **절대 최저가 필터는 서버에서 무시되므로** 감정가로 볼륨만 줄이고
   "최저가 ≤ 내 가용현금" 정밀 필터는 **로컬에서** 겁니다(`affordable_search`).
4. **페이지네이션** — 페이지당 40행(실측 상한, 200은 HTTP 400). `totalCnt` 도달 시 조기 종료.
5. **위장 헤더** — requests 기본 UA는 즉시 봇 차단. Chrome UA + `Referer`/`Origin`/`X-Requested-With` 등
   실측상 필수 6종을 붙여야 응답이 옵니다.

### 전국 샤딩 수집 (`load_courtauction_nationwide`)
전국 17개 시도를 **하나의 client로 순차 샤딩**합니다. client를 공유하므로 일일상한·지터·세션이
시도 전체에 **누적 적용**되어 밴을 피합니다. "1→700을 한 번에 훑는" 봇 패턴 대신 시도별로 구간을
쪼갭니다. 중간에 차단되면 **그때까지 모은 부분결과를 반환**하고 멈춥니다.

### 누락을 침묵하지 않음
- `max_pages` 상한에 잘리면 → `WARNING`으로 "몇 건 누락"을 로그에 명시(부산 등 대형 시도에서 수백 건이
  조용히 빠지던 버그를 감사에서 잡음).
- 잔여가 있는데 빈 페이지가 오면 → 서버 일시장애/조용한 차단으로 보고 `ERROR` 로그.

### 물건 상세 → 권리분석 (`courtauction_detail.py` · `courtauction_rights.py`)
목록 검색에는 **권리·임차·점유 정보가 없습니다.** 그 원재료는 물건상세의 세 문서에 흩어져 있습니다:
- **매각물건명세서**: 임차인 대항력·인수권리·특수권리(유치권 등)·소멸 안 되는 등기
- **현황조사서**: 실제 점유관계(공실/임차인/소유자점유)
- **감정평가서**: 감정평가액(시세 교차검증용)

파서는 저장된 텍스트에서 **불리언·금액·유형만** 뽑고(성명 등 PII 미저장), **애매하면 보수적으로
위험 쪽**(인수 있음·대항력 있음)으로 표시합니다 — 차익이 과대평가되어 위험 매물을 좋게 보는 침묵실패 방지.
현장 물건사진(`csPicLst[].picFile`)은 base64 JPEG 인라인이라 640px 썸네일로 리사이즈해 보관합니다.

## ② 국토부 실거래가 (molit) — 시세의 1순위 근거

`src/molit_client.py` (아파트/빌라/오피스텔) · `src/molit_extra_client.py` (단독·상가·토지) · `src/molit_cache.py`

시세의 **팩트**(실제 체결가) 소스입니다. 공공데이터포털 오픈API(무료, 운영자 키 필요).

### 엔드포인트 (물건유형별로 다름)
```
아파트    RTMSDataSvcAptTradeDev   (건물명 태그 aptNm / 아파트)
연립다세대 RTMSDataSvcRHTrade       (mhouseNm / 연립다세대)
오피스텔  RTMSDataSvcOffiTrade     (offiNm / 단지)
확장(선택) 단독·다가구(SH) · 상업업무(Nrg) · 토지(Land)
params: serviceKey, LAWD_CD(법정동 5자리), DEAL_YMD(YYYYMM), pageNo, numOfRows
```
응답은 **XML**. 거래금액은 `'34,500'`(만원+콤마) 형식이라 콤마 제거 후 ×10,000해 원으로 환산합니다.

### 수집 로직의 핵심 디테일
- **지역별(LAWD_CD) 호출**: 경매 물건이 실제로 있는 법정동만 호출합니다. 토지·상가만 있는 지역까지
  긁으면 시세추정에 안 쓰이면서 쿼터만 태워 429가 나므로, **아파트·오피스텔이 있는 법정동만** 대상.
- **다개월 창(live_months=12)**: 최근 12개월치를 수집해 표본을 확보(`recent_ymds`).
- **열린 달 vs 닫힌 달 캐시**: 이번 달+직전 달은 지연 신고 반영 위해 매번 재수집하고, 그 이전 달은
  `molit_cache`(SQLite)에 **영구 캐시**해 재크롤을 안 합니다. 재실행 비용을 크게 줄입니다.
- **병렬 fetch**: 국토부는 안티봇이 없어 ThreadPool(기본 8워커) 허용. 단 **쓰기는 메인스레드**에서만
  (SQLite 락 회피) — 워커는 받아오기만 합니다.
- **지역 태깅(중요 버그픽스)**: 각 거래에 그 호출의 `LAWD_CD`를 박습니다. 이게 없으면 전국 풀에서
  타지역 동명(서울 신정동 ↔ 대구 신정동)이 comps로 혼입돼 시세가 왜곡됩니다.
- **해제거래 제외**: 신고 후 취소된 거래(`cdealType="O"`)를 걸러냅니다(안 걸러내면 시세 +11% 부풀림, 실측).
- **마지막 페이지 판정**: 필터된 건수가 아니라 **원본 행 수**로 판정 — amount≤0으로 걸러진 행 때문에
  조기 종료돼 comps가 누락되는 편향을 방지.

### 키·오류 안전
- `serviceKey`는 로그·예외 메시지에서 **정규식으로 마스킹**(`serviceKey=***`) — requests가 URL에 키를 싣기 때문.
- 인증 실패/쿼터 초과는 조용히 빈 결과로 두지 않고 `MolitApiError`로 명확히 던집니다.

## ③ 네이버 부동산 (KB시세·호가·전세) — 시세 폴백

`src/naver_client.py` · `src/naver_match.py`

국토부 실거래가 **없는 물건**(거래가 드문 소형 오피·나홀로 단지)에 붙이는 폴백 시세 사다리입니다.

### 왜 Playwright인가
네이버는 토큰/쿠키 없는 순수 요청을 **429로 거부**합니다. 그래서:
1. Playwright로 실제 네이버 지도 페이지를 headless로 띄우고,
2. 페이지가 자기 API를 호출할 때 `authorization` 토큰과 세션쿠키를 **가로채(capture)**,
3. **페이지 컨텍스트 안에서 `fetch`** 를 실행합니다(쿠키·토큰이 자동으로 실림).

### 수집 항목
```
/api/cortars              좌표 → 법정동코드(cortarNo)
/api/regions/complexes    법정동 → 단지 목록
/api/complexes/{no}       단지 상세(면적타입 등)
/api/complexes/{no}/prices?provider=kbstar   KB시세 (호가 없을 때)
/api/articles/complex/{no}                   현재 매물 호가 목록
```

### 안전장치 (courtauction과 동일 철학)
- N건(기본 80)마다 브라우저 세션 갱신, 429는 30·60·90초 점증 대기 후 세션 재생성, 연속 429 3회면 중단.
- 200인데 JSON이 아니면(안티봇 챌린지 HTML) 조용히 None으로 삼키지 않고 **즉시 중단**.

### 단지 매칭 (`naver_match.py`)
경매물건(단지명·좌표·전용면적) → 네이버 단지(complexNo)·면적타입(areaNo) 매핑.
좌표로 법정동을 먼저 특정해 오매칭을 막고, 이름 유사도(RapidFuzz) + **전용면적 확증**으로 단지를 고릅니다.
음차/브랜드 표기(푸르지오/자이/e편한세상, STX·SC 등)는 **명시 등재 테이블**로만 변환합니다 — 일반 규칙으로
바꾸면 한글 음절과 겹쳐 브랜드명이 깨지기 때문(예: '푸르지오'→'푸르go').

## ④ 건축물대장 · 좌표 (부가 원천)

- **건축물대장** (`building_register_client.py`) — 건축HUB `getBrTitleInfo`(XML). 사용승인일로 **노후도**,
  위반건축물 여부로 **환금성·대출 리스크**를 정량화하는 뼈대.
- **좌표 변환** (`coords.py`) — courtauction의 `xCordi/yCordi`는 **KATEC(TM128)** 좌표계(실측 3,239건 전수대조
  98.4% 일치)라 WGS84로 순수 로컬 변환합니다(외부 API 0). 변환 결과가 물건 주소 시도 bbox를 벗어나면
  캐시에서 제외해 오좌표 핀을 구조적으로 차단.

## 캐시 & 증분 diff (`courtauction_cache.py`)

재실행 시 전체 재처리 대신 **달라진 것만** 봅니다:
- **신규**(새 매물) / **변경**(유찰→최저가 하락, 기일 변경) / **소멸**(낙찰·취하)을 사건번호+최저가+기일
  스냅샷 diff로 가려냅니다.
- **full-record 캐시**(`courtauction_full_cache.json`)는 정제된 원본 전체를 보존해, 오프라인 dry-run
  (`--from-cache`)이 실서버 호출 0으로 마지막 수집분을 그대로 재생하게 합니다(밤샘 오프라인 검증용).

## 매칭 → 시세추정 (`matcher.py`)

크롤한 경매물건과 실거래를 이어 붙이는 계층 매칭입니다. **비교군이 틀리면 통계가 아무리 좋아도 결과가
틀리므로**, 어느 집합에서 나온 시세인지(`scope`)를 신뢰 등급의 근거로 함께 반환합니다.

```
1) 같은 단지 + 같은 평형(±3%)   → same_complex_same_area  (추천 인정)
2) 같은 단지 + 인접 평형(±10%)  → same_complex_near_area  (참고치)
3) 같은 법정동 + 같은 유형·면적 → same_dong_fallback      (참고치 — 추천 금지)
추정시세 = (최근성 필터 → 이상치 트림 → 평단가 중앙값) × 전용면적
```

- **유형 분리**: 아파트를 아파트 실거래로만, 오피를 오피로만 평가(다세대↔아파트 혼입 차단). 시세추정은
  **아파트·오피스텔만** 지원 — 빌라·단독·상가·토지는 개별성이 커 "시세추정불가"로 분리(거짓 차익 방지).
- **감정가 교차검증**: 추정시세가 감정가의 2.5배(폴백은 1.5배)를 넘거나 0.6배 미만이면 비교군이 잘못됐다는
  신호로 보고 시세를 **말하지 않습니다**(과거 실사고: 같은 동 다른 단지 신축과 오매칭 4.5~11배).
- **표본 게이트**: 최근성·트림 후 실기반 표본이 3건 미만이면 밴드 생성 금지, 5건 미만이면 추천 제외.
- **2선 밴드**: 단일가는 정답처럼 보여 과신을 부르므로, 검증 하한가(보수)~기준가(중앙값) **두 선**으로 제시.

## 차익 스코어 (`score.py`)

```
score = ( 가격갭 × 0.50 + 권리 × 0.30 + 환금성 × 0.20 ) × 신뢰계수(0.6~1.0)
실질취득원가 = 최저입찰가 + 취득세 + 명도비 + 수리비 + 인수금액
가격갭       = (추정시세 − 실질취득원가) / 추정시세
```

| 하위점수 | 가중치 | 데이터 소스 |
|---|---|---|
| 가격갭 | 50% | 법원경매 최저가 + 국토부/네이버 시세 + 세율 룰 |
| 권리 깨끗함 | 30% | 매각물건명세서·현황조사서(courtauction 상세) |
| 환금성 | 20% | 실거래량 + 물건종류·지역유동성 |
| 신뢰계수 | ×0.6~1.0 | 실거래 매칭 표본수(3↑=1.0 / 2=0.85 / 1=0.7 / 0=시세추정불가) |

**하드게이트**: 인수금액/최저가 > 30% 또는 치명적 유치권이면 → 최종 스코어를 상한(25)으로 끌어내려
**"위험"으로 강등**합니다. (권리점수만 0으로 만들면 갭 50% 때문에 유치권 물건이 상위 노출되던 허점을 막음.)

**등급**: `차익 유력`(80+) · `양호`(60~79) · `관심`(40~59) · `주의`(<40) · `위험`(하드게이트) ·
`차익없음`(보수차익≤0) · `시세추정불가`(표본 부족) · `미지원유형`(아파트·오피 외) · `권리미확인`.

## 서빙 (Flask + Supabase 미러)

- 수집·채점 결과는 로컬 `auction.db`(SQLite)에 저장 후 **Supabase**(`auction_scored_listings`)로 적재합니다
  (`store_rest.py`). 웹은 직접 Postgres 접속 없이 **REST(service key)** 로만 읽어 Vercel/GitHub Actions 친화.
- 서빙 시점에 국토부가 없는 물건은 `market_view`로 **KB→호가→전세 폴백**을 라이브 적용합니다.

| 경로 | 설명 |
|---|---|
| `/` | 차익순 목록(갭미터·경고뱃지·필터 폼) |
| `/property/<사건번호>` | 물건 상세 — 시세근거·권리 안전성(하드게이트 사유)·환금성·사진·실거래 차트 |
| `/methodology` | 차익 스코어 공식·가중치·캘리브레이션 공개(투명성) |
| `/api/listings?min_score=80&type=아파트&region=서울&sort=profit` | JSON API |

## 실행

요구사항: Python 3.11+ (검증 3.14), 크롤에는 Playwright(네이버)·Pillow(사진).

```bash
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt   # Windows

# 샘플 데이터(네트워크 0)
python run.py

# 실제 법원경매 전국 크롤 + 국토부 라이브 시세 매칭 → auction.db 적재
python run.py --source courtauction --nationwide --cash 100000000 --live --live-months 12

# 오프라인 dry-run (실서버 호출 0 — 캐시/fixture로 파이프라인만 검증)
python run.py --source courtauction --from-cache --live-months 12
```

# 작업스케줄러 등록 (매일 05:30) — 등록 직후 상태는 반드시 Disabled(비활성)
